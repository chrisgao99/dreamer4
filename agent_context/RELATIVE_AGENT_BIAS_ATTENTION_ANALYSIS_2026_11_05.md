## 1. 结论摘要

1. RelativeAgentBias 是一个只看**当前位姿和类型**的几何先验，每次重规划计算一次，
   形状为 `(B, 8 heads, N query, N key)`。8 个 head 的数值各不相同，但同一个张量被所有层、
   所有 flow step、所有 chunk 共用。
2. 它对 attention 的影响很大：约占跨 key logit 方差的 40%，与 QK 内容项几乎不相关（r≈0）。
   只在某一层去掉它，该层约 30% 的 attention 质量会转移。
3. 它是唯一按 head 编号跨层共享的部件，因此打破了 head 置换对称性，让 head h 在各层带着
   同一个几何偏好（看自己/近处、看远处、看方向）。不过同一 head 跨层只有部分一致，QK 仍会逐层改变模式。
4. 它不含速度和时间：实际行驶中的 2310 与改成静止的 2310，bias 完全相同。
   导致碰撞的冲突车（从右侧垂直驶来的 2310）在任何 head 的先验里都不突出。
5. attention 权重不等于影响力：被关注最多的车往往不是决定行为的车。
6. 有直接证据表明“加 bias 但不改训练信号”不起作用：dynbias 的 FutureAgentBias 计算正确但几乎没被使用。
7. Steering（§10，opposing 单场景）：推理时给 ego→2310 的 bias 在所有 head 上加 +2 logit，
   ego 开始等待（启动 2.4 s → 6.45 s），ego 开过去撞上 2310 的比例 0.66 → 0.05；同样的 +2 加到其他车上没有作用。
   但总碰撞只从 0.81 降到 0.45，因为模型里的 2310 左转切得太紧，会撞上停在停止线的 ego。
   再给 2310→ego 加 +4 后碰撞降到 0.10。δ 过大（≥4）时效果不再针对 2310：对任何车都会让 ego 冻结或照搬对方。

## 2. 结构（已按代码核对）

### 2.1 RelativeAgentBias 本体

- 代码：`waymo/training/world_model/direct_action_flow.py` 中的 `RelativeAgentBias`；
  推理时 `waymo/scene_cache/sparse_agent_attention.py::patch_agent_attention(knn=0)`
  只是分块计算（`dense` 变体），数值与原实现相同。
- MLP：`Linear(7→128) → SiLU → Linear(128→8)`，每个 head 输出一个标量。
- 每一对有序车辆 (i, j) 的 7 个特征，都在 query 车 i 的坐标系下计算：
  `dx/100, dy/100, sin Δyaw, cos Δyaw, distance/100, same_type, (type_j − type_i)/4`。
  只用当前位姿，不含速度、历史、路径冲突或路权。
- 有方向：一般 `B[h,i,j] ≠ B[h,j,i]`。crossing 场景中，各 head 不对称程度的中位数为
  0.14 / 0.57 / 0.15 / 0.38 / 0.25 / 0.16 / 0.24 / 0.26。
  两车正面相对时，两个方向会近似相等（例如 ego↔628）。
- 每次重规划由 `encode_scene` 计算一次，得到 `scene.relative_bias`，形状 `(B, 8, N, N)`。

### 2.2 使用位置（crossing 场景实测：各处拿到的 bias 与 `scene.relative_bias` 最大差值均为 0）

| 位置 | 层数 | 传入形状（crossing，N=9） | 说明 |
|---|---|---|---|
| 场景编码器 agent self-attention | 4 | `(1, 8, 9, 9)` | 每层之前有 agent→64 条地图线的 cross-attention；再之前有 agent→64 个车道路径 token |
| 去噪器 `JointActionDiTBlock.agent_attn` | 8 | `(B·C=8, 8, 9, 9)` | 同一张 8×N×N 复制给 8 个 chunk；每次重规划跑 8 个 flow step |
| 去噪器 `scene_cross` 中车的部分 | 8 | `(B·N=9, 8, 1, N+64+64=137)` | query 车 i 的 bias 行接在 64 条局部地图 bias、64 个车道路径 bias 之后，在 [车 \| 地图 \| 路径] 上联合 softmax |

其余 attention 不带 relative bias：AgentHistoryEncoder（每辆车自己 11 帧历史，2 层）、
去噪器 `time_attn`（同一辆车 8 个 chunk 之间）、步级细化（chunk 内 5 步之间，2 层）。

### 2.3 带 bias 的 attention 计算（去噪器 agent_attn，单层）

对 query 车 i、chunk c、head h（head_dim = 256/8 = 32）：

```text
logit_j = q_{i,c}^{(h)} · k_{j,c}^{(h)} / sqrt(32) + B[h, i, j]     对场景中每辆车 j（含 i 自己）
alpha_j = softmax_j(logit_j)                                       在车之间归一化，而不是在 chunk 之间
out_{i,c}^{(h)} = sum_j alpha_j · v_{j,c}^{(h)}
```

- chunk c 只与各车的同一个 chunk c 交互；bias `B[h,i,j]` 对 8 个 chunk 相同。
- q、k、v 由同一个 `Linear(256→768)` 得到，但每个 head 是不同的 32 维投影。
  输入 token 先经过 LayerNorm，再按 flow time 做 adaLN 的 shift/scale。
- 8 个 head 拼成 256 维，经过 `W_o`，乘以 sigmoid gate（只依赖 flow time，所有车相同），再加回残差。
- 只有 bias 的相对大小有意义：对一行加同一个常数，softmax 不变。
  但在 `scene_cross` 中，车的 bias 行均值相对地图 bias 是有意义的，会影响车 token 与地图 token 之间的权重分配。
- 跨 chunk 的信息流靠同一辆车内部的 `time_attn`，逐层与 agent_attn 交替。
- chunk 0 = 将被执行的前 5 步动作。chunk token = chunk 动作嵌入 + 该车场景 token + chunk 位置编码。

## 3. bias 与 QK 内容项的数值对比

指标都是在同一行内、跨 key 的统计：

- `sd_qk` / `sd_b`：QK logit 与 bias 的标准差；
- `share_b = var_b / (var_qk + var_b)`；
- `corr`：两者跨 key 的相关；
- `TV(no bias)`：只在这一层去掉 bias（输入不变）时，attention 分布的总变差变化；
- `TV(bias only)`：真实 attention 与 `softmax(bias)` 之间的总变差。

## 4. 共享 bias 让 head 的角色跨层一致

方法：`head_consistency.py`。12 个 view，t=0，所有 query。相似度 = 1 − TV（对 query 行平均）；
去噪器的 attention 对 8 个 flow step 取平均。

| | 编码器（4 层） | 去噪器 agent_attn（8 层） |
|---|---|---|
| 同一 head、不同层 | 0.533 | 0.651 |
| 不同 head、不同层（对照） | 0.390 | 0.468 |
| 与自己 head 的 bias 先验 | 0.646 | 0.731 |
| 与其他 head 的 bias 先验 | 0.459 | 0.504 |
| 各 head 跨层优势（同 head − 不同 head）与 share_b 的相关（8 个 head） | +0.66 | +0.72 |

- 各 head 的跨层优势：编码器 0.16 / 0.21 / 0.09 / 0.15 / 0.36 / 0.07 / 0.07 / 0.04；
  去噪器 0.20 / 0.16 / 0.11 / 0.28 / 0.38 / 0.07 / 0.08 / 0.18。
- 跨模块（编码器 head h 对去噪器 head h）：同编号 0.581，不同编号 0.421。
  两个模块的参数完全独立，唯一共享的按 head 编号的部件就是 bias。
- 解释：普通 transformer 中 head 编号在层与层之间没有意义（同一层内重排 head，同时重排 `W_o` 的列，功能不变）。
  共享的 per-head bias 打破了这种对称性。bias 只保证角色跨层一致；角色本身是训练学出来的。
- 局限：几乎均匀的分布彼此本来就相似，所以只有“同 head − 不同 head”的差值是可靠信号。
  因果验证（例如在单层把 head 的 bias 循环错位）尚未做。

## 6. 相关证据：dynbias（FutureAgentBias）

- 改动：在 relative bias 之上，再加一个按 chunk、由自条件规划位姿计算的 agent-agent bias（零初始化）。
  代码在 `waymo/dynamic_agent_bias/`。
- stage-1 90k 的 512 场景评测（seed 12346，holonomic validity）与 laneconn stage-1 90k（只有 relative bias）对比：

| | ADE | minADE | CPD | 场景碰撞率 | 场景越界率 |
|---|---|---|---|---|---|
| laneconn 90k | 2.3819 | 1.3771 | 0.2212 | 0.417 | 0.395 |
| dynbias 90k | 2.2019 | 1.3103 | 0.2255 | 0.452 | 0.444 |

- 另一个会话用 `waymo/dynamic_agent_bias/check_future_bias.py` 做过检查（64 个场景）：
  FutureAgentBias 跨 key 的差异只有 0.25 logit（同一统计下 relative bias 是 0.79），
  强制关掉它时，执行的 5 步只变化约 2 mm。结论：新 bias 计算正确，但几乎没被使用，ADE 的提升大概率与它无关。
- 含义：不改训练信号（BC + 不含碰撞项的 MON），新增的 bias 不会被学起来，交互安全也不会改善。

## 8. 方法与注意事项

- attention 权重由 `attn_monitor.py` 用钩子重新计算：模型使用融合的 SDPA，不返回权重，
  因此以同样的 q、k、bias、mask 重算 softmax。
  自检：用重算的权重重建各层输出，与真实输出的最大相对误差为编码器 0.0045、agent_attn 0.0042、scene_cross 0.0055（bf16 舍入）。
- `TV(no bias)` 是“逐层、输入不变”的反事实。在整个网络里同时去掉 bias 属于分布外，是另一个问题。
- t=0 时同一场景的 8 条 rollout 历史相同，所以对 rollout 平均只影响去噪器（噪声不同）。
- 只覆盖 12 个 view、t=0；重点场景只有 2 个。

## 10. Bias steering 实验（opposing `95720e9471028705:6062`，ego 6062，冲突车 2310）

日期：2026-11-05。脚本：`wm_interaction_probe/bias_steer.py`（运行）、`bias_steer_report.py`（汇总、配对 CI、静止 ego 反事实）、
`bias_steer_video.py`（2×2 对比视频）。结果：`/p/yufeng/tri30/wm_interaction_probe/results/bias_steer/`
（`report.txt`、`report.json`；每组 (query, key) 一个目录，每个条件一个 npz；`videos/`）。

### 10.1 方法

- 在 `RelativeAgentBias` 的输出上，对选定 head 的 `B[h, query, key]` 加 δ（单位是 logit），每次重规划都加。
  可以只加在三处中的一部分：编码器 self-attention、去噪器 `agent_attn`（`scene.relative_bias`）、
  去噪器 `scene_cross`（`agent_memory_bias[..., :N]`）。默认 8 个 head、三处都加。模型权重不变。
  δ=0 时输出与不打补丁逐位相同。
- 128 条闭环 rollout，8 s，所有车联合生成（H40，每 0.5 s 重规划，`wm_common.rollout` 协议），bf16，seed 12346。
  各条件的噪声序列相同，因此按 rollout 编号配对，差值用配对 bootstrap 给 95% CI。各组的基线逐位相同。
- 碰撞：ego 与 2310 的 proxy 矩形（车辆 4.8×2.0 m，与 eval 相同）在任一步重叠。
  “真实尺寸”列用 log 中的尺寸（ego 5.29×2.33 m，2310 4.74×2.07 m）。
- “ego 停着被撞”：碰撞时 ego 距起点不到 1 m；“ego 行驶中撞”：其余碰撞。
- “静止 ego 反事实”：保留生成的 2310 轨迹，把 ego 固定在 t=0 位姿，看两者是否重叠。
  log 中 2310 与停着的 ego 最小间隙为 1.27 m，不重叠；log 中 2310 先过，ego 5.3 s 启动。
- 对照 key：2297（左前方 18 m、停在停止线的对向车）和 2319（42 m 外停着的车，基线中 ego 最关注的车）。
  2310 一侧的对照：2310→2319。
- attention 数值：t=0 第一次重规划，ego（或 2310）的 chunk-0 行，head 平均，去噪器对 8 层 × 8 flow step 平均。

### 10.7 结论与局限

- 对 §9.1 的判别问题，结论是行为随之改变，而且只对冲突车有效。
  这个模型中 2310 的 token 携带了能让 ego 等待的信息，只是 ego 的 attention 没有分给它，
  因为几何先验不偏向从右侧垂直驶来的车（§5.3）。所以至少在这一场景，信息路由是瓶颈之一，支持 §9.4 的 bias 重设计方向。
- 只修 ego 一侧不够：对方车也必须对 ego 有反应，这一场景近一半碰撞是 2310 自己切进停着的 ego。
- 有效窗口很窄（所有 head 约 +1.5 到 +2 logit；2310 一侧约 +4）。再大就出现无针对性的冻结（地图和路径信息被挤掉）
  或照搬对方 token 的内容。新的运动/冲突 bias 训练后，应该用 `bias_effect.py` 和本实验的对照方法检查它的量级是否落在有针对性的范围。
- 局限：
  - 只测了一个场景。
  - δ 是手工加给已知冲突车对的（oracle），只用于诊断，不能直接部署。
  - attention 只在 t=0 记录。
  - 碰撞用 proxy 矩形，真实尺寸下所有碰撞率都更高（两列都已给出）。
  - crossing 场景和更多场景的 steering 尚未做。

## 11. 另外两个场景：降低和提高 bias（2026-11-05）

### 11.3 三个场景合起来

- 去噪器 agent_attn 中“我对对方车的 attention”在这个模型里相当于一个让行信号。多看一点就更让，少看一点就更抢。
  这对 ego 和对方车都成立，有针对性的范围约为 ±1 到 ±4。
- 降低 ego 一侧会让 ego 更早走。是否碰撞取决于对方车是否补救：628 不补救，碰撞 3% → 17%；1282 改为直行，不撞。
  两侧都降低时，两个场景都出现碰撞（13–19%）。
- 提高 ego 一侧，中等 δ 有针对性，大 δ 无针对性地冻结，并带来追尾；逐 head 的角色在三个场景一致。
- 提高对方车一侧会让对方车让行，但让得不彻底时（crossing 中 628 只是减速），ego 抢走空档，反而撞上。
  只调一侧不能保证安全，需要两车的让行决策一致。
- 视频（同一 rollout、同一噪声的 2×2 对比）：
  - `3a99d1ec2d955550_619/videos/crossing_3a99d1ec2d955550_619_steer_rollout13.mp4`：基线 / ego→628 −8（撞）/ ego→624 −8 对照 / 628→ego +4（撞）。
  - `47e836ed96e19bda_1275/videos/opposing_47e836ed96e19bda_1275_steer_rollout6.mp4`：基线 / ego→1282 −8（1282 改为直行）/ 双向 −8（撞）/ ego→1282 +2（ego 等待）。
- 局限：仍然只有三个场景、手工选定的车对；对照 key 本身也有部分效果（尤其是被关注最多的车）；attention 只在 t=0 记录。

### 11.4 δ 的量级：为什么不同场景看起来需要不同的 bias

方法：`wm_interaction_probe/steer_scale.py`，结果在 `results/bias_steer/steer_scale.json`。
在 t=0 的第一次重规划（16 条）测 ego→冲突车的 attention（去噪器 chunk 0，head 平均），以及冲突车在 ego 收到的 value 加权写入中的份额。
行为数据取自 §10、§11 的 128 条 rollout。

| | opposing 2310 | crossing 628 | 47e8 1282 |
|---|---|---|---|
| 车数 N（均匀分配 1/N） | 31（0.032） | 9（0.111） | 32（0.031） |
| 基线 ego→冲突车 attention / value 份额 | 0.027 / 0.032 | 0.112 / 0.125 | 0.029 / 0.032 |
| +2 后 attention（相对基线的倍数） | 0.112（×4.1） | 0.331（×3.0） | 0.136（×4.7） |
| ego 启动 (s)：基线 | 2.40 | 3.70 | 2.85 |
| δ=−1 / −2 | 未测 | 3.00 / 2.50 | 2.20 / 2.00 |
| δ=−4 及以下（已饱和） | 2.00 | 2.0–2.1 | 1.8 |
| δ=+1 | 3.15（+0.75） | 4.55（+0.85） | 4.20（+1.35） |
| δ=+2 | 6.45（+4.05） | 6.30（+2.6） | 5.60（+2.75） |
| δ=+3 | 73% 不启动 | 59% 不启动 | 59% 不启动 |
| 对方车 t=0 速度 | 4.5 m/s（已在转弯） | 2.4 m/s（起步） | 0.4 m/s（停在线前） |
| 对方车→ego +2 的效果 | 几乎无效（碰撞 0.81 → 0.70），+4 才有效 | 减速 5.7 → 4.4 m/s | 左转 0.34 → 0.09 |

- **attention 的绝对量级确实不同。** crossing 大约是另外两个场景的 4 倍，但原因是车数不同：三个场景里冲突车拿到的都约等于均匀分配 1/N，模型并没有特别关注它。
  value 加权份额与 attention 几乎相等，所以也不是 value 大小不同造成的。
- **按 δ（logit）计，ego 一侧的反应三个场景几乎一致：** +1 推迟 0.75–1.35 s，+2 推迟 2.6–4 s，+3 都冻结；降低到约 −4 就饱和，相当于“删掉这辆车”。
  按 attention 绝对值计反而对不上：crossing 基线就有 0.112，ego 只等 3.7 s；opposing +2 后才到 0.112，ego 已经等到 6.45 s。
  也就是说，模型响应的是相对基线放大了多少倍（δ ≈ log 倍数），而不是 attention 的绝对值。
  三个场景中的 ego 都停在停止线上，状态相似，这可能是反应一致的原因；ego 在行驶中的场景未测。
- **“不同场景需要不同量级”有三个来源，都不在 ego 一侧：**
  1. 对方车的状态。停着的车（1282）+2 就能让它不左转；已经在转弯的车（2310）需要 +4。这与之前的探针结论一致：让行决策主要由速度决定。
     已经在动的车带着自己历史的惯性，而历史编码器和 time_attn 都不经过 bias。
  2. 碰撞是时间裕度上的阈值。启动时间随 δ 平滑变化，但能否翻转“撞/不撞”取决于场景本身的裕度：
     opposing 基线中 ego 与 2310 到达冲突区的时间几乎重合（81% 撞）；crossing 中 628 早就过去，要把 ego 提前约 1.7 s（降到饱和）才出现 17% 的碰撞。
  3. 方向不对称。降低有上限（删掉为止），能不能造成碰撞取决于“ego 不看就会撞”是否成立，以及对方车会不会补救。
     提高没有上限，但超过 +3 就变成无针对性的冻结；如果碰撞是对方车造成的（2310 切角），只提高 ego 一侧怎么调都不够。
- **对无关车的针对性：**
  - 降低完全有针对性：无关车 −8 时，三个场景的行为都不变。
  - 中等提高（+1/+2）对无关车基本无效，即使它拿到更多 attention（2319 +2 时为 0.31）。
  - 但本身多少相关的车（后方快速驶来的 1030、排队的对向车 1286）会产生部分等待效果。
  - 因此起作用的是“attention × 那辆车 token 中的内容”，而不是 attention 本身。

### 11.5 撞与不撞的 rollout，attention 有没有差别（对“朝不碰撞的 attention 做对比学习”的检验）

方法：`wm_interaction_probe/attn_vs_outcome.py`，结果在 `results/bias_steer/attn_vs_outcome.json`。
opposing 场景不加 steering，128 条 rollout，与 §10 基线逐位相同：104 条撞、24 条不撞。
记录前 4 次重规划（0–1.5 s）的 attention，按最终是否碰撞分组比较。AUC = P(碰撞 rollout 的值 > 不碰撞 rollout 的值)。

| 重规划 | 去噪器 ego→2310：撞 / 不撞 | AUC ego→2310 | AUC 2310→ego | 编码器 ego→2310 的跨 rollout 差异 |
|---|---|---|---|---|
| t=0 | 0.0265 / 0.0263 | 0.53 | 0.47 | 0（历史相同，完全一样） |
| t=0.5 s | 0.0312 / 0.0270 | 0.68 | 0.42 | 0.0055 |
| t=1.0 s | 0.0316 / 0.0251 | 0.72 | 0.57 | 0.0081 |
| t=1.5 s | 0.0321 / 0.0248 | 0.73 | 0.69 | 0.0084 |

- 在决策点 t=0，撞与不撞的 rollout 的 attention 没有差别。结果由噪声采样出的规划决定：撞的 rollout 中 ego 启动更早（中位数 2.3 s，不撞为 3.3 s）。
- 之后撞的 rollout 中 ego→2310 attention 反而更高。原因是两车已经更近，几何 bias 偏好近处的车，所以这是后果而不是原因。
  直接“朝不撞 rollout 的 attention 对比更新”会把 attention 往下推，与 steering 证明有效的方向（加大 attention 才会让行）相反。
- 含义：用同一场景的多次 simulate 做偏好或对比学习时，应该以结果（撞/不撞）作为偏好，让梯度穿过整个生成过程去更新参数，
  例如过滤式自蒸馏（MON 选择计入碰撞）、Diffusion-DPO、或只训练加了运动特征的 bias 模块。不要拿 attention 统计量作为目标。
