# 用"谁先过"变量 z 改进 WM 的交互：方案（2026-11-09，已与用户确认，尚未实现）

本方案的目标是改进 world model 在细节交互上的表现：减少碰撞，让通行顺序符合路权，并让车对对方的实际运动做出反应。做法是把"每对冲突车谁先过"做成 WM 内部一个有监督的 pair 变量 z，再把 z 变成去噪器 agent_attn 的 bias。小模型（pair head）先单独训练，再接入 WM。

## 1. 背景：为什么要改 representation，不是挑样本

**目标模型**：`waymo/checkpoints/waymo_daf_laneconn90k_mon8_gt_unroll80_b5_detach0_10k_20261009/best_ade.pt`。

- 结构：
  - 11 帧（1.1 s）历史；
  - 一次生成 40 步联合动作 (a_lon, a_lat, Δyaw)，执行 5 步后重规划；
  - 每次重规划 8 个 flow 步。
- 训练：`physical=False`，所以没有碰撞损失，`collision_weight=0.1` 并没有生效。
- 表现：
  - 轨迹看起来真实，能复现日志，也有足够的随机性；
  - 但部分场景的碰撞率达到 50–80%，重采样多少次都一样。

**已有证据**（细节见 `RELATIVE_AGENT_BIAS_ATTENTION_ANALYSIS_2026_11_05.md` §5、§10、§11，以及 `/p/yufeng/tri30/wm_interaction_probe/`）：

- **决策在 t0 的快照上就定了，之后不看对方怎么动。** 例如 ego 何时起步，由 t0 时冲突车的位置和速度决定。
  - 单条 rollout 内，起步时间与对方实际运动的相关约为 0。
  - ego 从不等冲突区清空。
- **两车没有协调。** opposing 场景里，联合采样的首个规划碰撞率是 79%，打乱配对后是 77%。
- **RelativeAgentBias 只用位姿，没有速度和时间。** 冲突车分到的 attention 约为 1/N。
- **steering 说明 attention bias 可以当"让行信号"用**（推理时手工加 δ；做法见第 3.6 节）：
  - ego→2310 +2 logit：ego 只对 2310 等待；加在无关车上没有效果。
  - 两侧都加：碰撞从 0.81 降到 0.10。
  - ≥3–4 logit：变成对任何车都冻结。
  - 量级大约是 +1 ≈ 多等 1 s，+2 ≈ 多等 3 s。
  - 合适的 δ 因场景而异：让停着的车让行 +2 就够，正在转弯的车要 +4。
  - 碰撞下限约 0.38，来自 2310 左转切得太狠。这是路径问题，z 修不了。
- **不能用 attention 统计量作目标。** 在 t0，撞和不撞的 rollout attention 相同（AUC 0.53）；之后撞的 rollout attention 反而更高，那是两车靠近的后果。
- **按违规挑 MoN 赢家没有用**（`waymo_daf_laneconn85k_mon8_select_{ade,constrained}_unroll80_b5_detach0_20261106`）：
  - 约 8.7k 步时，B 的 ADE 和 A 相同；
  - 同批次配对比较，B 的候选碰撞反而多约 7%。
  - 原因是日志本身没有碰撞，两种挑法的赢家都接近日志，梯度只是把赢家往日志拉，撞车的样本拿不到梯度。挑样本本质上就是换了权重的 BC。
- **BC 学不会交互的可能原因**：
  - 在 40 步的 flow loss 里，"晚 1 s 起步"只占很小一部分误差；
  - flow 可以把"走"和"等"都保留成模式，却不需要把选哪个和对方的状态联系起来。
  - 所以 80% 碰撞的场景里，"走"这个模式的概率本身就是错的。

**路权与通行顺序数据**：`/p/yufeng/tri30/waymo_interaction_screening/results/row_audit_step0_v5_20261105/`（SUMMARY.md、analysis/、pairs/）。

- 规模：421,825 对，2,331,398 行（pair × 时刻）。
- t0 路口、路权已知：train + val 共 85,580 对。
- 规则一（没空档时非路权方让）：各类型都成立，98.6–99.8%。
- 规则二（有空档时非路权方走）：成立比例依类型 36–92%。
- 准确率（validation）：
  - 匀速到达顺序 0.911；
  - MLP（距离 + 速度）0.952，困难子集 0.869；
  - MLP 加路权 0.969，困难子集 0.931。
- 本方案讨论时补算的数字（t0、路口、路权已知，含 test，n = 90,151）：
  - 非路权方没空档却先过（"抢行"）：只有 585 对，其中 550 对路权方确实减速了。
  - contested pair 里，第二辆车从 t0 起进入冲突区的时间中位数是 6.0 s，p75 7.0 s，比 4 s 的规划窗口长。
  - 各类型的量足够跨场景学习，例如无控制左转 12,507 对，许可左转（一方灯态）12,198 对。

## 2. z 的定义与真值

- **冲突对**：沿用审计的定义（`row_audit_extract.py` 的 `pair_rows`）。
  - 两车日志路径有空间重叠就算，判据是中心距 < 两车半宽之和 + 0.5 m，不要求同时到。
  - 每车第一次进入重叠区的帧是它的进入帧，早的为先。
  - 第 5 帧前已在冲突区的对（`pre_existing`）去掉，同帧进入的对（`tie`）也去掉。
- **类别**：z_ij ∈ {i 先, j 先, 无冲突}。z 由两车共用，并且是反对称的。
- **每次重规划在时刻 t 重给标签**：
  - 两车都还没进入：按日志里的先后。
  - 先过的车还在冲突区里：仍标"它先"，让行信号保持到冲突区清空。
  - 先过的车已经离开：标"无冲突"。
- 注意："无冲突"这一类也透露了路线（例如对方右转而不是左转）。把 z 当潜变量可以接受，但 head 必须能从历史和路线里预测它。
- 训练时刻要在接近过程中均匀采样。不要用 L10/L20 这种从进入时刻往前倒推的锚点，它们会泄露时间。

## 3. 设计

### 3.1 pair head（单独训练的"小模型"）

- **输入**：
  - 两车的 agent 表示；
  - 显式 pair 特征：相对位姿和速度、到冲突点的距离和时间、lane graph 上的冲突关系、路权 r_ij（有、无、未知）加类型 embedding，以及对方是否已在冲突区里。
- **输出**：p(z_ij)，用交叉熵训练。
- **结构要求**：以紧凑的 pair 特征为主，容量小。这样它靠结构跨场景泛化，而不是记住某个路口（见 3.5）。
- **路权未知的对**（路口 pair 的约 42%）：r=0，不要丢掉。训练时再随机把一部分 r 置为未知，避免模型过度依赖标签。

### 3.2 z → bias：bias 没有单独的目标

- **形式**：b_ij^h = g(z_ij, pair 特征)，每个 head 一个数。
  - 用 `3·tanh` 限幅；
  - **零初始化**，训练第 0 步与原 WM 完全一样；
  - 只加在去噪器的 agent_attn 上。scene_cross 在 δ 大时会挤掉地图 key，所以不加。
- **训练目标**：就是 WM 原有的 flow loss，拟合日志轨迹，训练时把真值 z 喂进去（teacher forcing）。
  - 梯度回答的问题是："已知对方先过，bias 取多大能让日志轨迹的似然最大"。
  - 所以 bias 的大小按场景学：g 的输入有 pair 特征，同样是"对方先"，停着的车和正在转弯的车可以得到不同的 bias。
  - bias 太大也会受罚：车等太久就与日志不符，flow loss 会把它压回去。固定 δ 时出现的"ego 一直不起步"，在这里直接是损失。
  - WM 本来就对的场景：知道 z 几乎没有新信息，梯度很小，g 只需要不破坏原来的行为。
- **z-dropout**：一部分样本把 z 置为"未知"。
  - 这提供了一个无条件模式，供推理时第一次采样（见 3.4）。
  - 每个场景的 loss(真值 z) − loss(z 未知)，就是"知道谁先过"的信息量。它可以直接显示哪些场景在被改、改了多少。
- **flow loss 里只能用真值 z 或"未知"，不能用 head 预测错的 z。** 否则日志和 z 互相矛盾，WM 会学会忽略 z。head 的错误由它自己的 CE 和校准来管。
- **闭环 unroll 训练时**：rollout 一旦明显偏离日志，日志里的先后可能不再成立。这些重规划改用"未知"。
- **训练顺序**：先只训练 g 和 pair head，WM 本体冻住，然后再用小学习率解冻去噪器。

### 3.3 为什么这样能改 representation

- 通行顺序标签来自日志，不依赖 WM 的样本，所以在 80% 碰撞的场景里同样有效。
- pair head 的 CE 梯度进入编码器，逼它把"谁该先走"分开。
- dynbias 的教训是：只加特征、没有对应的训练信号，模型就不用。CE 和 teacher-forced 的 flow loss 就是这个训练信号。

### 3.4 推理

1. 每次重规划时，先有路线，再算 r 和 z，最后由 g 给 bias 并生成计划。
   - 第一次重规划：先用 z=未知 采一次计划，取每辆车的路线，算出 r 和 z，再带 bias 采正式计划。
   - 之后每次：用上一次计划剩下的 35 步当路线。
2. z 由 head 采样，每对车只采一个，两车共用。这样从构造上就不会两车都走。
3. 重算 p(z) 时加滞后：变化足够大才换 z，避免来回翻。对面抢行时 p(z) 会翻过来，这就是"反应"。
4. 路权标注器本身就是"路径 + 地图 + 灯态"的函数，可以直接跑在 WM 的计划上。因为推理时的路线来自 WM 计划，比日志路线更噪，训练时要给路线加噪。

### 3.5 日志之外的分支（例如日志里 A 直行，rollout 里 A 左转，路权随之改变）

单纯用日志监督保证不了这些分支，有两个缺口要补：

1. **同一场景的其他分支没有标签，只能靠跨场景泛化。**
   - head 监督的是一个函数：(两车路线, 状态, 路权) → 谁先过。"A 左转、对向直行车有路权"在别的场景的日志里出现过上万次。
   - 前提一：z 和 r 必须按这个分支自己的路线重算（见 3.4）。否则两个分支输入相同，z 不可能不同；z 按日志路线采、WM 却走另一条路线时，两者还会互相矛盾。
   - 前提二：head 不能记住场景（见 3.1）。
2. **WM 会走到日志里没有的状态**：两车都蹭进冲突区、距离已经很近、路径切得太狠。日志里险情极少，这是 BC 典型的分布偏移。做法类似 DAgger，在 WM 自己的 rollout 上加不依赖日志的标签：
   - 已在冲突区里的车就是先过的车（按定义）；
   - 没空档（margin_N ≤ 0）而且停得下：非路权方让，98.6–99.8%；
   - 停不下（需要的减速度 > 3 m/s²，即两条规则里拟合出的 A=3）：这辆车先过。
   - 规则判断不了的，用 head 自己的预测。
   - 用这些标签训练 head，并把 z 喂给 g。这些分支上 g 没有轨迹目标，但有两个不需要日志的损失：碰撞损失，以及 rollout 实际的先后顺序与 z 一致。
   - 有空档、规则二只有 36–92% 成立的格子，本来就没有确定答案，只用 head 从日志里学到的概率，不给硬标签。

### 3.6 干预训练（补上日志里没有的"对方意外动作"）

- 做法：把一辆车的日志未来沿它自己的路径整体提前或推后 0.5–3 s（"错时"），作为强制执行的车。
- 其余车的目标：
  - 碰撞损失；
  - 扰动后由 head 或规则给出的通行顺序；
  - 离冲突远的车贴近原模型。
- 这样"对面抢行了也得躲"有了明确的目标。如果只有"别撞"，模型会学成 steering 里看到的那种无差别减速。

steering 当时的加法，供对照：
- 8 s rollout 的 16 次重规划都加同一个常数 δ。每次重规划里，bias 只算一次，所有层（4 层编码器、8 层去噪器 agent_attn、scene_cross）和 8 个 flow 步共用。
- gated 版本只在两车仍在接近时才加（最后 0.1 s 内距离缩小 > 0.02 m）。碰撞同样低（0.10 和 0.06），"ego 一直不起步"减半（0.25→0.12，0.36→0.15）。
- 学出来的 g 相当于把这个开关变成连续的：z 变为"无冲突"或对方离开后，bias 自然关掉。

## 4. 执行步骤

0. **WM 失败分格表**（只需推理）。
   - 在 ROW 已知的 pair 上采样 WM，并存下样本。
   - 按"路权类型 × margin_N"分格，统计碰撞率和 P(N 先过)，与 SUMMARY 表对比。
   - 把碰撞分成三类：顺序没定（协调问题，z 能修）、顺序定了但间隔太短（执行问题）、路径切得太狠（路径问题，z 修不了）。三类的比例决定第 3–5 步的比重。
1. **标签。**
   - 先做 v5.1：约 10% 的 signal_red_partial pair 在冲突前红灯变绿，这些标为未知。
   - 在每个训练时刻重算路权和 z。
   - 按 scenario_id + track id 对接到 WM 数据（50k ooi_centered 或全量 scene cache）。不能按 shard 顺序对接。
2. **单独训练 pair head**，输入与 WM 一致（1.1 s 历史、WM 的地图和灯态、每 0.5 s 一个时刻），做两版：
   - A1：自己的小编码器加显式 pair 特征；
   - A2：同样的 head，但读冻结的 best_ade.pt 编码器 token。
   - A2 明显不如 A1：信息不在 representation 里，需要第 3 步用 CE 改编码器。
   - A2 ≈ A1：信息在，只是没被用上，主要靠 bias 通道。steering 的结论偏向这一种，但只看了一个场景。
   - 参照值：MLP 加路权在 t0 困难子集上 0.931。还要检查校准是否能复现 SUMMARY 表。
3. **接入 WM，WM 冻住**：pair head 加 CE，g 加 z-dropout，用 teacher-forced z 的 flow loss 训练。用 `bias_effect.py` 确认冲突 pair 上的 bias 在 2 logit 左右，不到 4。
4. **小学习率解冻去噪器**，加 DAgger 式规则标签、z 一致性损失和碰撞损失。
5. **加错时干预训练。** 需要的话，再在所有候选上加碰撞损失或 flow-DPO（mon-select 的结论也指向这一步）。有了 z 的约束，不容易学成无差别冻结。

## 5. 评估

- 512 场景 eval：ADE、minADE、CPD、碰撞率。还要看"ego 一直不起步"和冻结车辆的比例，防止碰撞下降只是因为车不走了。
- 三个 steering 场景，用同样的配对种子：95720e9471028705:6062、3a99d1ec2d955550:619、47e836ed96e19bda:1275。
- 第 0 步的分格表在训练后重做：
  - margin_N < −1 的格子应接近 0%（日志 0–2%）；
  - 有空档的格子应接近日志的比例；
  - 按路线分组（例如 A 直行和 A 左转的 rollout），分别看碰撞率和先后顺序是否符合各自的路权。
- head 本身：通行顺序的准确率和校准，在日志状态和 WM 状态上分开报告。
- z-dropout 的信息量分布：哪些场景依赖 z。

## 6. 风险与未决事项

- head 预测错的 z 会被 WM 执行。这只能靠 head 的校准，以及重规划时重新评估来纠正。
- 路线噪声：推理时的路线来自 WM 计划，与训练用的日志路线有偏移。
- 路径切得太狠造成的碰撞，z 修不了，需要地图、路径方面的损失。
- 环岛、灯态未知等"未知"类只能靠运动学。全向停车的到达判定偏紧。
- 多车同时争一个冲突区时，各对的 z 可能互相矛盾（出现环），第一版不处理。
